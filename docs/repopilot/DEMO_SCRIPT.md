# 3–5 分钟演示脚本

准备：运行 README 中的 setup、migrate、`pnpm repopilot:dev`；注册自己的本地测试账号。打开 `http://localhost:3000/repopilot`。演示开头说明“这是录制数据的离线演示，模型文本固定；LangGraph、任务、鉴权和数据库是真实执行”。

## 0:00–0:45 输入与任务

展示 Karakeep 原首页和左侧 RepoPilot 入口。输入 `https://github.com/langgenius/dify`，技能选 TypeScript/Python，周期两周，目标作品集。点击开始；HTTP 返回任务后进入详情。Mock 很快，可能直接看到完成，不伪造缓慢进度动画。刷新证明任务与报告从数据库恢复。

## 0:45–1:30 Agent 决策与证据

展开执行轨迹，指出采集、痛点分析、相关技术检索、两次证据缺口检查和一次定向补查。实际补查读取 issue #43455；缘由是独立样本少且正文截断，补查不保证消除缺口，所以警告仍在。次数来自执行计数，不是预设“思考过程”。

显示报告的录制时间、5 条 issue 样本、open/closed 状态。点击证据打开 GitHub；也可运行 `pnpm repopilot:smoke:github` 展示动态 API 核对。说明“存在该 issue”不代表“当前版本仍未解决”。

## 1:30–2:45 三个方向与约束

依次展示人工介入恢复检查器、并行工具运行诊断面板、应用依赖健康检查助手。查看目标用户、AI 技术匹配、已有能力、最小范围、验证实验与风险。指出每个方向低置信度、评分只是启发式；目标指标尚未实测。打开来源摘录，确认论点需要人工复核，不能仅凭链接存在认定建议正确。

## 2:45–3:45 收藏、反馈、导出

点击保存原 GitHub 项目并确认；再次保存展示重复安全。回到原 Karakeep 收藏列表查看书签。离线启动器只运行研究 worker，网页抓取尚未执行，不能说已成功抓取全文。

点击“有帮助”和“标记采纳”，刷新后查看记录。复制或下载 Markdown，展示来源 URL、风险、评分和假设。历史列表可以重新进入或删除任务。

## 3:45–4:30 失败与边界

可输入另一仓库触发明确的 Mock 无夹具错误，再展示重试会新建记录。真实模式缺密钥时不会偷偷调用其他模型。说明当前 Live LLM、Meilisearch、原 crawler DNS 尚待环境配置/验证。
